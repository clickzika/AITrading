API Reference

AITrading · FastAPI backend · Base URL: http://localhost:8000

Base URL: All endpoints are relative to http://localhost:8000. WebSocket connects to ws://localhost:8000/ws. Authentication uses JWT Bearer tokens — see the Authentication section.

Authentication

Single-user system. Password login returns a JWT access token (24h expiry). Pass the token as Authorization: Bearer <token> on all protected endpoints.

POST

/auth/token

public

Exchange password for JWT access token. Rate-limited to 10 requests/minute per IP.

Content-Type: application/x-www-form-urlencoded

FieldTypeRequiredDescription
usernamestringREQUIREDAlways "trader" (single-user system)
passwordstringREQUIREDConfigured via TRADER_PASSWORD env var
# curl example
curl -X POST http://localhost:8000/auth/token \
  -d "username=trader&password=your_password"
200OK — token issued 401Invalid password 429Rate limit exceeded

  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",

}
POST

/auth/refresh

JWT required

Issue a new token using a valid (not yet expired) existing token. Extends the session without re-entering the password.

# No body needed — pass existing token in Authorization header
curl -X POST http://localhost:8000/auth/refresh \
  -H "Authorization: Bearer <current_token>"
200New token 401Token expired or invalid

TradingView Webhook

Receives alert payloads from TradingView Pine Script. Signature-verified via HMAC-SHA256.

Signature Verification: Every request must include X-TV-Signature header: hmac-sha256=<hex> where hex = HMAC-SHA256 of the raw request body with your TRADINGVIEW_WEBHOOK_SECRET. Requests without a valid signature return 401. Verification uses hmac.compare_digest (constant-time) to prevent timing attacks.
POST

/webhook/tradingview

HMAC signed

Receives TradingView strategy alerts. Parses the payload, queues a signal to Redis pub/sub, and persists to TimescaleDB.

/api/trades/order

JWT required

Place a market order directly via MT5. Risk manager enforces lot limits and daily loss cap before sending to MT5. Order is written to DB (status=PENDING) before MT5 call — audit trail is never lost.

WebSocket

Connect to ws://localhost:8000/ws?token=<jwt> for real-time updates. The JWT is passed as a query parameter (headers not supported in browser WebSocket API). The server sends events on every tick and candle close.

WS

ws://localhost:8000/ws

JWT via query param
ParamTypeDescription
tokenstringrequiredJWT access token from /auth/token
symbolsstringoptionalComma-separated symbols to subscribe. Default: all
// JavaScript connection example
const ws = new WebSocket(
  `ws://localhost:8000/ws?token=${jwtToken}&symbols=XAUUSD,EURUSD`
);

ws.onmessage = (evt) => {
  const event = JSON.parse(evt.data);
  switch (event.type) {
    case 'tick':        handleTick(event); break;
    case 'candle_close': handleCandle(event); break;
    case 'signal':       handleSignal(event); break;
    case 'position':     handlePosition(event); break;
    case 'risk':         handleRisk(event); break;
  }
};

Error Codes

All error responses follow RFC 7807 Problem Details format.

{
  "type":    "https://aitrading.local/errors/risk-limit-breach",
  "title":   "Risk Limit Breach",
  "status":  400,
  "detail":  "Order rejected: would exceed daily loss cap of $200",
  "code":    "RISK_DAILY_CAP"
}
HTTPCodeMeaning
400RISK_DAILY_CAPOrder would breach daily loss cap
400RISK_MAX_POSITIONSMax open positions reached
400RISK_LOT_TOO_LARGELot size exceeds max lot limit
400SIGNAL_ALREADY_EXECUTEDCannot cancel executed signal
401AUTH_INVALIDWrong password or invalid JWT
401WEBHOOK_INVALID_SIGHMAC signature mismatch
401TOKEN_EXPIREDJWT has expired
403FORBIDDENValid token but insufficient permission
404NOT_FOUNDResource not found
422VALIDATION_ERRORPydantic validation failure (field details included)
429RATE_LIMITEDToo many requests — retry after Retry-After seconds
503MT5_CIRCUIT_OPENMT5 circuit breaker open — auto-trading paused
503MT5_DISCONNECTEDMT5 connection lost
500INTERNAL_ERRORUnexpected server error
