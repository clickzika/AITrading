System Overview

Purpose

AITrading is a Windows-hosted automated trading system connecting MetaTrader5 broker execution to a configurable strategy engine backed by multi-indicator technical analysis. The system runs 24/5 during Forex market hours, evaluating YAML-defined strategies on candle close events and executing orders via MT5 with hard risk management enforcement.

Analysis Engine Specification

5.1 MACD

Computed via pandas_ta.macd(close, fast=12, slow=26, signal=9). Output: MACD line, signal line, histogram. Signal states: bullish_cross (MACD crosses above signal), bearish_cross, bullish (histogram positive), bearish.

5.2 EMA

Computed via pandas_ta.ema(close, length=N) for each configured period. Cross detection compares last two values: if EMA_fast[i] > EMA_slow[i] and EMA_fast[i-1] < EMA_slow[i-1] → bullish_cross.

5.3 Fibonacci Retracement

Swing high/low identified using pandas_ta.swing_analysis on a configurable lookback period (default: 20 candles). Standard levels: 0, 23.6, 38.2, 50, 61.8, 78.6, 100%. Level price = swing_high - (range × ratio). Recomputed per candle close only.

5.4 Fibonacci Time Zones

From a reference swing start candle index, project future candle indices at Fibonacci multiples: 1, 2, 3, 5, 8, 13, 21, 34... of the reference swing duration. Output: list of future bar timestamps that are Fibonacci time projections.

5.5 Volume Profile (VPVR)

Aggregates volume by price level over configurable window (default: 200 candles). Divides price range into 50 bins. Identifies Point of Control (POC), Value Area High (VAH), Value Area Low (VAL) using 70% volume rule. Implemented as VolumeProfileService — no external library dependency.

5.6 SMC — Order Blocks

Bullish Order Block: last bearish candle before a bullish Break of Structure. Valid while price has not traded back through its midpoint. Bearish Order Block: mirror logic. Algorithm:

  1. Detect BOS (price closes above/below last swing high/low)
  2. Look back for the last opposing candle before the BOS candle
  3. Store OB zone as {high, low, direction, valid: True}
  4. Invalidate OB when price closes through the 50% level of the zone

5.7 SMC — Fair Value Gaps (FVG)

Detected when candle[i].low > candle[i-2].high (bullish FVG) or candle[i].high < candle[i-2].low (bearish FVG). The gap zone = {top, bottom, direction}. FVG considered filled when price trades into the zone. Partial fill tracked when price partially enters the zone.

5.8 SMC — BOS / ChoCH

BOS: price closes beyond a prior swing in the same direction as trend. ChoCH: first BOS in the opposing direction. Swing structure maintained as sorted list of swing highs/lows. Market structure state: BULLISH | BEARISH | RANGING, updated on each BOS/ChoCH detection.

5.9 Liquidity Sweeps

SSL Sweep: candle wick extends below prior swing low then closes above it (liquidity taken, then rejection). BSL Sweep: mirror. Detection: candle.low < prior_swing_low AND candle.close > prior_swing_low. Output event: LiquiditySweepEvent with direction, swept_level, candle timestamp.

5.10 Candlestick Patterns

Detected using TA-Lib CDL functions on last 3 candles. Supported patterns:

  • Hammer / Inverted Hammer
  • Bullish / Bearish Engulfing
  • Doji (standard + gravestone + dragonfly)
  • Morning Star / Evening Star
  • Pin Bar (wick > 2× body, close in top/bottom 25%)
  • Shooting Star

5.11 Wick Fill

Identifies candle wicks that point to unfilled price areas. A wick fill setup exists when: (1) prior candle has a prominent wick (wick ≥ 2× body), (2) the wick area has not been revisited in the last N candles, (3) current price is approaching the wick level from the opposite side.

5.12 Stop Loss Sweep Detection

Detects classic stop hunt pattern: (1) price makes new swing low/high (triggers stops), (2) strong rejection candle forms, (3) price closes back above/below the sweep level. Reported as SLSweepEvent for strategy entry triggers.

Condition Evaluator Logic

Strategy evaluator receives an IndicatorSnapshot and evaluates each condition against it. Conditions return True/False. Combined with logic AND (all must pass) or OR (any must pass). If combined result is True, a SignalEvent is emitted.

Money Management Algorithms

MethodAlgorithm
Fixed Lotlot = config.lot_size
Fixed Fractionallot = (account_balance × risk_pct%) / (sl_pips × pip_value)
Kelly Criterionkelly_f = win_rate - (1-win_rate)/rr_ratio; lot = account_balance × kelly_f × 0.5 / (sl_pips × pip_value)
Half-Kelly applied for safety. Min lot 0.01.

News Trading Mode

When a strategy has news_filter: true, the strategy engine checks the economic calendar before each signal emission. High-impact events within ±30 minutes (configurable) of the current time cause signal suppression. Post-event re-entry can be triggered on first candle close after event window.

HFT Scalping Mode

When execution_mode: hft, strategy evaluates on every MT5 tick rather than candle close. Signal conditions limited to price-action-only (no MACD/EMA recompute per tick — too slow). Tick-level SL/TP in points. Max position duration enforced (configurable, default 60s).

Execution Engine Specification

MT5 Client

Wraps MetaTrader5 Python library. Key methods:

class MT5Client:
    async def connect(self) -> bool
    async def get_account_info(self) -> AccountInfo
    async def get_symbol_info(self, symbol: str) -> SymbolInfo
    async def get_latest_candles(self, symbol: str, timeframe: str, n: int) -> list[CandleData]
    async def place_market_order(self, intent: OrderIntent) -> MT5OrderResult
    async def place_pending_order(self, intent: OrderIntent) -> MT5OrderResult
    async def close_position(self, ticket: int) -> MT5OrderResult
    async def modify_sl_tp(self, ticket: int, sl: float, tp: float) -> bool
    async def get_open_positions(self) -> list[Position]

Order Manager

Receives OrderIntent from Money Manager. Sequence:

  1. Write OrderIntent to trades table with status PENDING
  2. Call MT5Client.place_market_order
  3. On success: update trade record with mt5_ticket, status → OPEN
  4. On failure: update trade record status → CANCELLED, log error
  5. Start trailing stop monitor if configured

Grid Manager

Maintains a grid state per strategy instance:

  • Grid initialized at first signal — base price set, N levels above/below calculated
  • Each level tracked: price, direction, lot_size, status (pending/filled/closed)
  • On price reaching a level: place corresponding order
  • On grid level fill: re-place at next outer level (infinite grid) or stop at max_levels
  • Grid state persisted in Redis for crash recovery

Risk Manager Hard Limits

These checks run before every order — never bypassed:

  • Daily loss cap: if risk_state.trading_halted = true → reject all new orders
  • Max open positions: if open count ≥ limit → reject (per symbol and global)
  • MT5 disconnected: if mt5_client.connected = false → reject and alert
  • Max lot size: lot capped at symbol max lot regardless of money management output
